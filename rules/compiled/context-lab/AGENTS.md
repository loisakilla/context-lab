# Правила для агентов: context-lab

## Ключ посетителя не покидает браузер

Ключ Anthropic посетителя хранится только в его браузере и уходит напрямую в api.anthropic.com. Сервер лаборатории не логирует промпты и ключи; iframe превью работает без `allow-same-origin`.

_Применяется к: apps/lab/**_

<!-- context-lab/key-stays-in-browser@1.0.0 -->

## Внешние действия только по просьбе

Не делай push, публикацию пакетов, деплой, отправку сообщений и любые другие внешние действия без явной просьбы пользователя. Локальный коммит допустим, когда пользователь попросил сохранить работу.

<!-- org/ask-before-publish@1.0.0 -->

## Пропсы только через type checker

Пропсы компонентов извлекай только через TypeScript Compiler API с настоящим `ts.Program` и type checker. Синтаксический разбор без проверки типов не используй: он ломается на пересечениях, обёртках React и наследовании.

_Применяется к: packages/docgen/**_

<!-- context-lab/type-checker-only@1.0.0 -->

## Контраст текста не ниже 4.5:1

Обычный текст и плейсхолдеры держат контраст не ниже 4.5:1 к своему фону, крупный и жирный — 3:1. Приглушённый серый на светлом фоне — самая частая причина нечитаемого интерфейса: если сомневаешься, двигай цвет в сторону основного текста. Статусные цвета проверяй в обеих темах: палитра, подобранная на тёмном фоне, на светлом обычно проваливается.

_Применяется к: **/*.tsx, **/*.css_  _Тип задач: ui, fix_

<!-- org/contrast-floor@1.0.0 -->

## Сначала воспроизведение, потом правка

Прежде чем править баг, воспроизведи его: тест, который падает на текущем коде, или точная последовательность шагов в отчёте. Правка без воспроизведения лечит симптом. Тест на найденный баг остаётся в наборе навсегда.

_Тип задач: fix_

<!-- org/reproduce-before-fix@1.0.0 -->

## Одна реализация инструментов

Инструменты поиска и выдачи API живут в `@context-lab/index-tools` и обслуживают одновременно MCP-сервер и браузерный tool use. Не дублируй их логику в других пакетах.

_Применяется к: packages/**_

<!-- context-lab/one-tool-implementation@1.0.0 -->

## Клавиатура и фокус обязательны

Всё, что делается мышью, делается с клавиатуры: Tab проходит по порядку чтения, Escape закрывает слой, после закрытия фокус возвращается на триггер. Кольцо фокуса видно и не убирается через `outline: none`. Действие, доступное только по наведению, считается недоступным.

_Применяется к: **/*.tsx_  _Тип задач: ui_

<!-- org/keyboard-and-focus@1.0.0 -->

## Все состояния, а не только счастливый путь

У интерактивного элемента есть `hover`, `focus-visible`, `active`, `disabled`; у экрана с данными — загрузка, пустота и ошибка. Пустое состояние объясняет, что делать дальше, а не пишет «ничего нет». Проверяй вёрстку на длинном и коротком тексте: перенос и обрезка входят в дизайн.

_Применяется к: **/*.tsx_  _Тип задач: ui_

<!-- org/states-before-happy-path@1.0.0 -->

## Проверки делает компилятор

Сгенерированный код проверяет `@context-lab/checks` на `typescript` и `@typescript/vfs`. Не заменяй проверку типов регулярными выражениями по коду; линтер только дополняет компилятор.

_Применяется к: packages/checks/**, packages/runner/**_

<!-- context-lab/compiler-checks@1.0.0 -->

## Ответы в бюджете токенов

Каждый ответ инструмента укладывается в бюджет токенов. При переполнении сообщай, какие разделы опущены и как их запросить точечно; молчаливая обрезка запрещена.

_Применяется к: packages/**_

<!-- context-lab/token-budget@1.0.0 -->

## Рефакторинг не меняет поведение

Рефакторинг оставляет наблюдаемое поведение и публичный API прежними: тесты проходят без правок, иначе это уже изменение поведения и оно идёт отдельным коммитом. Переименования и переносы файлов не смешивай в одном коммите с правкой логики.

_Тип задач: refactor_

<!-- org/refactor-keeps-behavior@1.0.0 -->

## Документация показывает рабочий пример

Описание без примера бесполезно: к каждому компоненту и публичной функции идёт короткий пример, который компилируется и взят из настоящего API, а не придуман по памяти. Пример показывает типичный случай целиком, а не фрагмент из середины.

_Применяется к: **/*.md_  _Тип задач: docs_

<!-- org/docs-show-usage@1.0.0 -->

## Анимация объясняет состояние

Анимируй только переход состояния: появление, уход, отклик на нажатие. Вход и выход идут на `ease-out` за 150–250 мс, `ease-in` не используй — он делает интерфейс вязким. Анимируй `transform` и `opacity`, а не `width`, `height` и отступы. Действие, которое пользователь повторяет десятки раз за день, не анимируй вовсе.

_Применяется к: **/*.tsx, **/*.css_  _Тип задач: ui_

<!-- org/motion-conveys-state@1.0.0 -->

## Логика приходит с тестами

Новая логика в `packages/*` приходит с тестами на vitest. MCP-сервер проверяется сквозным тестом через настоящий stdio-клиент из SDK. Перед коммитом прогоняй `npm run verify`.

_Применяется к: packages/**_

<!-- context-lab/tests-required@1.0.0 -->

## У анимации есть вариант без движения

Каждый блок с анимацией сопровождай `@media (prefers-reduced-motion: reduce)`: переход схлопывается в мгновенный или в смену прозрачности. Движение — это украшение поверх работающего интерфейса, а не условие, без которого он не показывается.

_Применяется к: **/*.css, **/*.tsx_  _Тип задач: ui_

<!-- org/reduced-motion@1.0.0 -->

## Тест называет поведение, а не метод

Имя теста читается как утверждение о поведении: «возвращает пустой список, когда совпадений нет», а не «тестирует search». Проверяй наблюдаемый результат, а не внутренние вызовы: тест, который знает о реализации, ломается на каждом рефакторинге.

_Применяется к: **/*.test.ts, **/*.test.tsx_  _Тип задач: test_

<!-- org/test-names-behavior@1.0.0 -->

## Пакеты экспортируют исходники

Пакеты монорепо экспортируют исходники (`exports: ./src/index.ts`); сборка в `dist` нужна только публикуемым пакетам. Относительные импорты внутри пакетов пишутся с расширением `.ts`.

_Применяется к: packages/**/package.json_

<!-- context-lab/source-exports@1.0.0 -->

## Долговременная память в Obsidian

Если пользователь ссылается на прошлую работу, решение или «что мы делали раньше», сначала найди это в хранилище Obsidian через MCP: фильтруй по проекту и дате во frontmatter и читай только нужные заметки. Заметки о сессиях не пиши сам: их экспортирует планировщик.

<!-- org/memory-in-obsidian@1.0.0 -->
